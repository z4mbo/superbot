# Superbot parity inventory

The [November 20 Rakazo comparison](rakazo-comparison.md) covers the full trees, RPC contracts and hosted harness after integrating upstream `9c773a5aa`. The entries below also document earlier client and reference-app checks.

## Baselines and evidence

- **Installed Windows Grok Bot:** executable product version **1.2.3.0**, packaged `package.json` version **1.2.3**. Read the installed `resources/app.asar` header and selected packaged JavaScript directly. The entry point is `dist/electron-main/main.cjs`. The renderer loads `dist/renderer/assets/index.eager-app-DodVIpEt.js`, with `dist/electron-preload/preload.cjs` and separate main-process, local execution, node-coordinator and meeting-recorder bundles. Bundle identifiers below establish shipped code, with account access, backend behavior and current rollout unknown. The packaged avatar engine was also compared against the private local study copy. Personal appearance files stay on the user's devices.
- **OpenMausBot Simple:** local `simple-only` ref at `52eabf28913482585d13fcc577ec29bf00f08f6f` is the tailored UI reference. Read that Git ref directly. The default checkout at `9748010` has `SIMPLE_ONLY = false` and can switch interface modes. The Simple-only tip removes product surfaces such as rooms, cloud and automations even where related modules remain. For those broader OpenMausBot workflows, inspect the default checkout with Simple mode selected in source, or identify the feature as retained code. For example, reproduce the conversation trace with `git show simple-only:src/components/bot-panel/Conversations.tsx` and `git show simple-only:src/state/store.tsx`.
- **Rakazo and Superbot.** The local Rakazo baseline is `c742a079990dca34a69ea6090b953c852b82ebdf`. Superbot release `dde9e62fb1a1` was deployed on NixOS with agent computers enabled and restricted egress verified. Web routes are registered in [App.tsx](../../apps/web/src/App.tsx), chat sheets and settings are mounted by [Shell.tsx](../../apps/web/src/pages/Shell.tsx), and request schemas and dispatch live in the [shared contract](../../packages/contracts/src/rpc/app-contract.ts) and [API router](../../apps/api/src/router.ts).

**Web** means an existing Rakazo control reached through the signed-in server web app. **Service** means an RPC or HTTP operation the server offers.

## Verification

- **Interactive plugin views.** A marketplace tool can return a view through the existing sandboxed MCP App viewer. The isolated API and worker fixture exercised the temperature converter, checked that the approved resource was served to the issuing conversation and checked the effect of revoking access. [Runnable converter](../../examples/plugins/marketplace-unit-converter/README.md) · [PostgreSQL fixture](../../packages/testkit/src/product/marketplace-mcp-app.postgres.test.ts)
- **Agent computers.** In an undated NixOS fixture check, Firefox displayed two isolated Linux desktops. Keyboard input reached the intended terminal on each desktop. Their homes and networks were separate. Both could reach public HTTPS. Connections to the host, metadata and the other desktop were blocked. A different session and the screen URL alone were refused. Handing back control invalidated the earlier interactive connection. Windows WebView2 was also exercised with a synthetic provider through Watch, Take control and Hand back.

### Inbox and conversation Library

- Inbox RPCs `inbox/list` and `inbox/setState` use durable foreground run state for the signed-in member in the selected Space. A run moving from active to result gets a new item. A new pending card on a run gets its own receipt key. Read and done survive reloading. The list covers up to 100 recent run candidates and returns conversation and message anchors. Prompts and card fields stay in the authorized thread view.
- The `conversationLibrary/list` RPC accepts an explicit bot conversation, default bot or group target. The list returns up to 100 authorized references from the latest 500 messages. Artifact rows identify the downloadable version and uploader. Page rows require owner access. App rows contain an opaque ID and a message anchor for the run owner. Opening an app depends on the existing chat viewer. Storage keys, hidden HTML, tool arguments, tool results and internal screenshots stay out of Library responses.
- The [shared contract](../../packages/contracts/src/threads/conversation-content.ts) defines both. Run changes use the existing Space run signal. Inbox receipt changes publish a content-free roster signal for that member.

- The [disposable PostgreSQL fixture](../../infra/superbot/verify-conversation-content.mjs) exercised two members, two Space scopes, explicit sibling conversations, durable receipt changes, successive pending questions, private page visibility, file attribution and hidden app artifact exclusion.
