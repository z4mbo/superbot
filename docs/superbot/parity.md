# Superbot parity inventory

## Baselines and evidence

- **Installed Windows Grok Bot:** executable product version **1.2.3.0**, packaged `package.json` version **1.2.3**. Read the installed `resources/app.asar` header and selected packaged JavaScript directly. The entry point is `dist/electron-main/main.cjs`. The renderer loads `dist/renderer/assets/index.eager-app-DodVIpEt.js`, with `dist/electron-preload/preload.cjs` and separate main-process, local execution, node-coordinator and meeting-recorder bundles. Bundle identifiers below establish shipped code, with account access, backend behavior and current rollout unknown. The packaged avatar engine was also compared against the private local study copy. Personal appearance files stay on the user's devices.
- **OpenMausBot Simple:** local `simple-only` ref at `52eabf28913482585d13fcc577ec29bf00f08f6f` is the tailored UI reference. Read that Git ref directly. The default checkout at `9748010` has `SIMPLE_ONLY = false` and can switch interface modes. The Simple-only tip removes product surfaces such as rooms, cloud and automations even where related modules remain. For those broader OpenMausBot workflows, inspect the default checkout with Simple mode selected in source, or identify the feature as retained code. For example, reproduce the conversation trace with `git show simple-only:src/components/bot-panel/Conversations.tsx` and `git show simple-only:src/state/store.tsx`.
- **Rakazo and Superbot:** local Rakazo `upstream/main` is `c742a079990dca34a69ea6090b953c852b82ebdf`. The server comparison includes Superbot release `d4b771ee7139`. Native observations include the Windows build tested on November 20, 2026. Rakazo web routes are registered in [App.tsx](../../apps/web/src/App.tsx), chat sheets and settings are mounted by [Shell.tsx](../../apps/web/src/pages/Shell.tsx), and request schemas and dispatch live in the [shared contract](../../packages/contracts/src/rpc/app-contract.ts) and [API router](../../apps/api/src/router.ts). Hosted rollout and authenticated production behavior are unknown.

**Native** means a reachable GPUI control. **Web** means an existing Rakazo control reached through the signed-in server web app. **CLI** means a user-facing terminal operation. **Service** means Rust can call an operation. **Partial** means a listed part of the workflow is reachable. **Absent** means the inspected entry points lack the workflow or its prerequisite contract. **Unknown** means the bundled code or source is insufficient to establish access. Rows are source evidence unless the verification section identifies an exercised workflow.

[Open web workspace](../../native/desktop/src/app.rs) takes the current selection to `/app/:botId`, `/app/:botId?threadId=:threadId`, `/app/g/:groupId` or `/app`. On Windows it opens the server client in a separate WebView2 profile keyed by origin and native account. Web authentication and Space access still apply. Other platforms open the browser. The workspace renders Rakazo's web interface. Electron-specific integrations, provider popups, browser permissions and downloads require individual verification. ## Verification and implementation order

- **Current offline verification:** read installed resources without starting Grok Bot, inspected both Git baselines, and checked UI handlers against the shared contracts and API handlers. Ran `cargo test --locked -p superbot-features -p superbot-cli`: 55 passed and one installed-provider probe was ignored. Those tests exercise CLI approvals and isolated local CLI behavior, plus loopback wire fixtures for files, approvals, teams, routines, boards and model configuration. Relative documentation links and `git diff --check` passed. No authenticated production visit or provider session was used.
- **Recorded isolated end-to-end evidence:** the [chat verification log](chat-verification.md) records the installed CLI and temporary PostgreSQL server with a synthetic model for direct chat, synchronized retry/history, second-member group streaming and a granted marketplace skill. Those results cover the described runs and versions. They establish neither an embedded WebView2 flow nor a Grok workflow.
- **P0. Conversation navigation.** The isolated two-member fixture covered explicit conversations, sibling isolation, shared rename/pin/archive/restore and web links. The native Inbox opens message anchors in the correct conversation. Outstanding work includes project moves, title generation and individual conversation deletion.
- **P0 — Reachable web handoff.** Exercise sign-in and current-conversation handoff from a clean per-origin/account profile. Verify role and deployment gating, then go through one fixture action for artifacts, plugins, provider callbacks and computer controls. For provider/media flows use local emulators or mark them unverified. Provide a feature-specific web destination when there is one and an actionable availability state when there is none.
- **P1. Library navigation and older history.** Verify native resource opening with synthetic artifacts and add pagination for older references. Keep file versions, private pages and computer paths subject to their own access controls.
- **P1 — Media, computers, catalogs and collaboration.** Verify media permissions, external-auth callback isolation, signed screen control release, and supported local computer/recording behavior. Treat catalog rights, identity, install grants and team access as product contracts before adding imports or migration. Keep provider, deployment and platform gating visible in the parity record.

### Inbox and conversation Library

- Inbox RPCs `inbox/list` and `inbox/setState` use durable foreground run state for the signed-in member in the selected Space. A run moving from active to result gets a new item. A new pending card on a run gets its own receipt key. Read and done survive reloading. The list covers up to 100 recent run candidates and returns conversation and message anchors. Prompts and card fields stay in the authorized thread view.
- The `conversationLibrary/list` RPC accepts an explicit bot conversation, default bot or group target. The list returns up to 100 authorized references from the latest 500 messages. Artifact rows identify the downloadable version and uploader. Page rows require owner access. App rows contain an opaque ID and a message anchor for the run owner. Opening an app depends on the existing chat viewer. Storage keys, hidden HTML, tool arguments, tool results and internal screenshots stay out of Library responses.
- The [shared contract](../../packages/contracts/src/threads/conversation-content.ts) and [Rust client methods](../../native/features/src/conversation_content.rs) back the [desktop Inbox](../../native/desktop/src/ui/inbox.rs) and [per-conversation Library](../../native/desktop/src/ui/agent_panel/library.rs). Run changes use the existing Space run signal. Inbox receipt changes publish a content-free roster signal for that member.

- The [disposable PostgreSQL fixture](../../infra/superbot/verify-conversation-content.mjs) exercised two members, two Space scopes, explicit sibling conversations, durable receipt changes, successive pending questions, private page visibility, file attribution and hidden app artifact exclusion. The native wire test exercised Inbox target decoding, Library lookup and receipt mutation over loopback HTTP.
