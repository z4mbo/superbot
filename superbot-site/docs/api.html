Registry API

The pluginRegistry namespace of the server's typed RPC. Every procedure needs a signed-in session and acts in the selected Space.

Procedures

ProcedureInputResult
submit{ slug, version, manifest }The version, status pending
mine{ after?, limit? }Your versions, any status
submissions{ status?, after?, limit? }Review queue; status defaults to pending. Admins only
review{ versionId, decision: "approved" } or { versionId, decision: "rejected", reason }The decided version. Admins only
discover{ slug?, query?, after?, limit? }Approved versions. Search by name, ID or description.
install{ versionId }The installation, pinned to that version
switchVersion{ installationId, expectedVersionId, versionId }Same installation with a new approved version and zero grants.
installations{ after?, limit? }Your installations in the Space
setGrants{ installationId, botId, partIds }The installation with its current grants
uninstall{ installationId }{ ok: true }

Objects

Paging

List procedures take limit from 1 to 50 (default 20) and an opaque after cursor, and return { items, nextAfter }. nextAfter is null on the last page.

Rules

  • slug and part ids: 1 to 64 characters matching ^[a-z0-9]+(?:-[a-z0-9]+)*$. version: a whole number from 1.
  • The first submission reserves a slug for its publisher. Rejected versions keep it reserved. Each new version is a separate submission and review.
  • A version is decided once. Rejecting needs a reason of 1 to 2,000 characters.
  • Installing the same version again returns the existing installation. To change versions, pass its current plugin.id as expectedVersionId to switchVersion. A successful switch clears old grants. Repeating a completed switch preserves any new grants. On a conflict, read the current installation before retrying.
  • New installations have no grants. setGrants replaces one bot's parts; an empty partIds revokes them. uninstall removes every grant at once.
  • The registry never contacts tool servers or runs anything from a manifest.

Errors

StatusWhen
401No session, or it expired. Sign in again.
403review or submissions from an account that isn't a deployment admin.
400The input or manifest doesn't match the schema.

The exact schemas live in packages/contracts/src/integrations/plugin-registry.ts in the repository.
