superbot-plugin commands

The author and admin tool for the plugin registry. Registry commands print JSON.

Options for every command

OptionWhat it does
--server URLThe Superbot server. Also read from SUPERBOT_SERVER. Use the same one you signed in to with superbot login.
--space NAME|IDWhich Space to act in, by exact name or ID. Needed only if you belong to more than one.

Writing and publishing

CommandWhat it does
init SLUG [--name NAME] [--manifest FILE]Writes a starter manifest with one skill part, summary. Alias scaffold. The file defaults to plugin.json.
validate [FILE]Checks the manifest against schema 1 locally, without contacting the server.
publish SLUG VERSION [--manifest FILE]Submits a version for review. VERSION is a whole number from 1. Alias submit.
status VERSION_IDShows one of your versions, its status and any rejection reason.

Lists

list SCOPE [--after CURSOR] [--limit N], where N is 1 to 50 (default 20). When there's another page, the JSON includes nextAfter; pass it as --after with the same scope and filters.

ScopeLists
discoverApproved versions. The default. Filter with --slug SLUG.
mineYour own submissions, with their status.
installationsYour installations in the selected Space, with their grants.
submissionsThe review queue, for deployment admins. Filter with --status pending|approved|rejected.

Installing and granting

CommandWhat it does
agentsLists the selected Space's bots and their ids, for grants.
install VERSION_IDInstalls an approved version into the selected Space.
set-grants INSTALLATION_ID BOT_ID [PART_ID...]Replaces that bot's parts for the installation. No part ids revokes them all. Alias grant.
uninstall INSTALLATION_IDRemoves the installation and every grant it has.

Reviewing

CommandWhat it does
review VERSION_ID approvedApproves a pending version. Deployment admins only.
review VERSION_ID rejected --reason TEXTRejects it. The reason is required and shown to the publisher.
