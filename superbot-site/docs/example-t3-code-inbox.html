Example: T3 Code inbox

Bots write coding requests into a record app. You read each request, pick a T3 Code project and start it there yourself. Nothing reaches T3 Code until you choose to start it.

This example uses the same parts as any plugin: two record apps and a skill. The connection to T3 Code is not part of the plugin. It runs on your computer, in a command-line companion, after you approve it.

What you'll learn

  • How several app parts and a skill split a job between bots and people.
  • Why a part a bot should never write stays ungranted.
  • How retries stay safe when a local program writes records through the registry API.

Requirements

  • A Superbot server where the T3 Code inbox is in Discover. A server publishes the bundled inbox, slug t3-code-inbox, unless another publisher already holds that slug.
  • T3 Code on your computer or reachable over HTTPS, with its MCP address from Use T3 Code in another app (MCP).
  • A Superbot checkout with Node.js and the workspace dependencies installed.

The manifest

The repository keeps it in examples/plugins/t3-coding/manifest.json. It is the same manifest the server publishes.

PartKindFields or contentWho uses it
requestsapptitle, brief (text, required)Bots propose; people read and add
dispatchesapprequest-id, thread-id, run-id, thread-link, status (text, required)Receipts written for the operator. Keep it ungranted
request-guideskillHow to write a short title and a self-contained brief, with no credentialsBots

Step 1: Install and grant

  1. In Store → Plugins → Discover, install T3 Code inbox in the Space where bots should propose work.
  2. On its page, grant Requests and Request guide to each bot that proposes requests. Leave Dispatches off for every bot, so only you write receipts.
  3. Ask the bot to propose a coding request. Check the title and brief on the approval card and choose Allow once. You can also add a request yourself in the Requests app.

Step 2: Start a request

The companion in examples/plugins/t3-coding starts approved requests from a Superbot checkout. Sign in to T3 once, then list, add and dispatch requests. Use your real addresses; the ones below are placeholders.

The companion asks for your Superbot password and signs out when it exits. Add --email-code on a server that sends sign-in codes. Each dispatch is one approval by you. The companion is a one-shot command: it never dispatches in the background and offers no remote service.

Retries and receipts

  • Each start uses one T3 request ID, saved before T3 is called. If T3's reply is lost, start the same request again with the same connection and project. T3 returns the original thread instead of starting a second one.
  • A retry with another project, a changed brief or a different T3 connection is refused. Check T3 Code before doing anything else.
  • If T3 started the thread but the receipt couldn't be saved, the companion keeps the receipt locally until it can write it. It doesn't call T3 again.
