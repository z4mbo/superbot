Get started

Build for Superbot

A Superbot plugin is one JSON manifest. It can give bots instructions, connect them to your service, or add a record app that people and their bots keep together. A reviewer approves each version, and people choose which bot gets which part.

ToolThe address of an MCP server you hostYour server, over public HTTPSYour tools, each call approved by a person, with an optional view in chat

A plugin has 1 to 16 parts in any mix. The T3 Code inbox, for example, has two record apps and a skill.

How a plugin reaches a bot

  1. Write the manifest with superbot-plugin init or Create plugin in the store, and check it with superbot-plugin validate.
  2. Publish a version under a slug. Your first submission reserves the slug on that server.
  3. Review. A deployment admin approves or rejects the exact version. Approved versions never change.
  4. Install. Anyone on the server can install an approved version for their own account in a Space. It adds nothing to any bot yet.
  5. Grant. The installer turns on parts for each bot, one bot at a time.
  6. Use. Bots read skills and list entries freely. Every tool call and every entry they add waits for Allow once.

People, bots and permissions covers each rule.

Ways to build

ToolGood for
Create plugin in the storeWriting a record app, skill or tool part with a form and submitting it. On the web: account menu, Integrations → Community. On desktop: Plugins
superbot-pluginStarters, local validation, publishing, review and grants from a terminal, on Windows, macOS or Linux
Registry APIPrograms that publish, install or read and write record app entries

All three use the same manifest, so a plugin.json moves freely between them.

What a plugin can't do

  • Carry credentials, HTTP headers, commands, packages, scripts or install hooks. The server stores the manifest and never runs code from it.
  • Reach a bot that nobody granted it to, or write without a person's approval.
  • Bring its own pages into Superbot. Record apps use Superbot's form and list; a tool's view runs in a sandbox with no access to the app.
  • Reach private or local network addresses. Tool servers must be public HTTPS.

The server Superbot builds on can also add plugins from a public GitHub repository, in a different plugin.json and mcp.json format. These docs cover the reviewed Superbot store.
