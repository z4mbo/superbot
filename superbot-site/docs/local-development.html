Get started

Local development and testing

Develop against a server only you use. You publish, review and install there as often as you like, then submit the finished version to a shared server once.

Your own server

From the checkout root, with Node.js 24.15 or later and Docker Compose 2.24.4 or later:

  • The web app is at http://127.0.0.1:5173. Use init --port PORT for another loopback port.
  • node infra/superbot/host.mjs logs shows startup output. down stops the stack and keeps its data.
  • For a second stack, pass a unique --project NAME and a separate --env FILE to every command.
  • On Windows without Docker, infra/superbot/windows-local.ps1 start runs the same services from the workspace.

Become a reviewer

Reviewing needs a verified account whose email is in SUPERBOT_ADMIN_EMAILS. Without mail, create a verified account with the bootstrap command:

  1. In .env.superbot.local, set SUPERBOT_ADMIN_EMAILS to your email. Separate several reviewers with commas.
  2. Export OWNER_EMAIL and OWNER_PASSWORD (at least 16 characters), run node infra/superbot/host.mjs account, then remove both variables from your shell.
  3. Run node infra/superbot/host.mjs up to apply the setting.

The account can then open Review in the store and run superbot-plugin list submissions.

The edit loop

Approved versions never change, so each change is a new version number. On your own server that costs a few seconds:

Switching keeps the installation and clears its grants, so grant again after each switch. Record apps keep separate entries per version: switching back shows the earlier version's entries.

  • validate catches every manifest error without the server. Run it first.
  • For tool servers, run your server on loopback and call it with curl as in Test locally. The registry only accepts public HTTPS endpoints, so a published tool part needs your deployed address.

Fixtures and tests

The repository's fixtures start disposable servers on loopback ports with synthetic accounts and a deterministic model. They never touch your own data.

Reset and clean up

  • To remove a plugin from your account, superbot-plugin uninstall INSTALLATION_ID. This deletes a record app's entries.
  • Slugs stay reserved, even for rejected versions. On your own server, choose a new slug or start a fresh stack with another --project.
  • node infra/superbot/host.mjs down stops the stack and keeps its volumes.

Move to a shared server

  1. Sign in to the shared server: superbot server https://superbot.example.com, then superbot login.
  2. Check that your slug is free there, then superbot-plugin publish SLUG 1. Version numbers are per server.
  3. Wait for its reviewers. superbot-plugin status VERSION_ID shows the decision and any reason. See Review, install and versions.
