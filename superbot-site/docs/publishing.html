Plugins

Review, install and grants

A version moves from pending to approved or rejected once. After approval, people install it into a Space and choose, bot by bot, which parts that bot may use.

On desktop, open Plugins at the bottom of the sidebar. In the web app, open the account menu, choose Integrations and select Community. Both stores show the registry of the server you signed into.

Review

Choose Create plugin, describe what the plugin does and add its skills or tool endpoints. Submit a version for review. A deployment reviewer can inspect its parts in Review and approve it or return a reason for rejection. To address feedback, publish a new version of the same plugin.

StatusWho sees itWhat happens next
pendingThe publisher, and deployment admins in the review queueAn admin approves or rejects it. It can't be installed.
approvedEveryone signed in to the server, through discoverPeople can install it. It never changes.
rejectedThe publisher, with the reviewer's reasonFix it and submit a higher version number.
  • Deployment admins are the accounts the server operator lists in RAKAZO_ADMIN_EMAILS. Publishers can't review their own submissions unless they are admins.
  • A decision is final. A rejection needs a reason of 1 to 2,000 characters.
  • The first submission reserves the slug for its publisher, and a rejected version keeps it reserved.

Install

In Discover, search by name or description. Open a result to inspect the skill instructions and remote tool destinations before choosing Install.

Installing puts an approved version into the selected Space for your account. Installing the same version again returns the same installation. An installation is pinned to its exact version.

Grants

Open the plugin under Installed. Select a bot and turn on the parts it needs. Turn a part off to revoke that bot's grant. Other bots keep their own settings.

A new installation starts with no grants: no bot can use any part yet. A grant gives one bot one part.

  • Each call replaces that bot's whole list of parts for the installation. Leave the part ids out to revoke them all.
  • Other bots need their own grants.
  • Removing a grant and adding it back creates a new grant, so approvals that were waiting on the old one don't carry over.

What a granted bot can do

  • Skills reach the bot as Markdown it can read, treated as untrusted input.
  • Tools are listed for the bot, and every call shows an approval card with the tool, its endpoint and the exact arguments. Nothing is sent until a person chooses Allow once. In a Space set to Never ask, calls are refused.
  • After approval the server checks the grant again, checks the tool's schema still matches what was approved, and refuses redirects and private addresses. A request already sent may finish after a grant is revoked.

Updating and uninstalling

  1. Publish a higher version number and have it approved.
  2. Open the installation in the store, choose an approved version and confirm the switch. On the command line use superbot-plugin switch-version INSTALLATION_ID CURRENT_VERSION_ID TARGET_VERSION_ID.
  3. Choose which agents can use the new release. Switching clears the previous grants in the same transaction. If the switch fails, the current release and grants stay in place.

To remove the installation and its grants, use superbot-plugin uninstall INSTALLATION_ID.
