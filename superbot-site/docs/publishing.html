Publish

Review, install and versions

A version moves from pending to approved or rejected once. After approval, people install it for themselves, grant parts bot by bot, and move to newer versions when they choose.

Where the store is

Open Store → Plugins in the desktop or web sidebar. In the compact web sidebar, open the account menu to find Store. This shows the registry of the server you signed in to, with Discover, Installed and Create plugin, and Review for reviewers.

Submit a version

In Create plugin, describe the plugin, add its apps, skills or tool endpoints, set the identifier and version, and choose Submit for review. From a terminal:

StatusWho sees itWhat happens next
pendingThe publisher, and reviewers in the queueA reviewer approves or rejects it. It can't be installed
approvedEveryone signed in to the server, in DiscoverPeople can install it. It never changes
rejectedThe publisher, with the reviewer's reasonFix it and submit a higher version number

Your first submission reserves the slug on that server for your account, and a rejected version keeps it reserved.

Review

Reviewers are verified accounts the operator lists in SUPERBOT_ADMIN_EMAILS. In Review, they inspect every part, including skill instructions, record app fields and tool endpoints, then approve or give a reason for rejecting. Approval checks each tool endpoint against the public-address policy. A decision is final; a rejection needs a reason of 1 to 2,000 characters.

When reviewing, check that each part does one job a person can grant on its own, that skills ask for nothing secret, and that labels say what a bot will see.

Install

In Discover, search by name or description and open a result to see its parts before choosing Install. The installation belongs to your account in the selected Space, pinned to that exact version. Installing the same version again returns the same installation.

Grants

Open the plugin under Installed, select a bot and turn on the parts it needs. A new installation has no grants, and each bot needs its own.

Each call replaces that bot's whole list for the installation; leave the part ids out to revoke them all. What a granted bot can then do is in People, bots and permissions.

Ship a new version

  1. Publish a higher version number and have it approved. Keep part and field ids the same when they do the same job.
  2. Each installer chooses when to move: open the installation, choose the approved version and confirm. From a terminal, superbot-plugin switch-version INSTALLATION_ID CURRENT_VERSION_ID TARGET_VERSION_ID.
  3. Switching keeps the installation and clears its grants in the same step, so the installer reviews the new version and grants again. If the switch fails, nothing changes. If the current version changed meanwhile, list installations again and retry.

Record app data

Each version of a record app keeps its own entries. After a switch the installer sees the new version's entries, and switching back shows the earlier ones again. Turning off a grant keeps the entries. More in Record apps.

Uninstall

Uninstalling removes the installation and every grant it has, and permanently deletes a record app's entries for every version. Leaving the Space does the same.
