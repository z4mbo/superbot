Tools and MCP views

A tool part points at an MCP server you host. Granted bots can call its tools after a person approves each call, and a tool can return an interactive view that appears in chat.

How a tool call works

  1. A person grants your mcp part to a bot. Superbot opens a connection to your endpoint and lists its tools.
  2. The bot asks to call a tool. The approval card shows your endpoint, the tool and the exact arguments.
  3. After Allow once, the server checks the grant and the tool's schema again, then sends tools/call. Redirects and private addresses are refused.
  4. The result goes back to the bot. If the tool declares a view, the web app shows it in a sandboxed card under the result.

Write the server

Start from the TypeScript starter, which needs Node.js 24 and no packages:

It writes plugin.json, server.ts and a README with a local test request. Despite its name, mcp-app is a tool server, not a record app.

  • Support MCP initialization, tools/list and tools/call over Streamable HTTP. Keep listing free of side effects: Superbot lists before anyone approves.
  • Give each tool a short description and a JSON object input schema with its required fields. Validate the arguments again on your server.
  • Return structured results for data the bot should use.
  • Treat the endpoint as public and set your own rate limits. If your service needs sign-in, use OAuth on your side; a manifest can't carry credentials.
  • Superbot exposes up to twenty tools per granted endpoint.

Add a view

A view is an HTML document your server serves as an MCP resource. Superbot shows it under the tool's result after the approved call succeeds.

  1. Advertise the resources capability when initializing.
  2. In tools/list, set the tool's _meta.ui.resourceUri to a ui:// URI.
  3. Answer resources/read for that exact URI with mimeType: "text/html;profile=mcp-app" and the document in text.

The card runs your document in a sandbox with an opaque origin and no cookies or storage. It receives the call's arguments and result after it initializes. Right after the person clicks or types in it, it can open a link, which they confirm, or offer text to the composer, which they send. It can't call tools. A view that hasn't started within 15 seconds isn't shown, and the bot's reply stands without it. The repository's examples/plugins/marketplace-unit-converter has a complete view in temperature.html.

Deploy and publish

The registry refuses local HTTP addresses, so put the server behind a public HTTPS reverse proxy. Keep the listener bound to loopback, set the manifest's endpoint to the exact public /mcp URL, and publish. Reviewers' approval checks the endpoint against the public-address policy.

Publish a new version whenever the manifest or a tool's contract changes incompatibly. Superbot binds each approval to the tool's schema, so a changed schema can't reuse an old approval.
